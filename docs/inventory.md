# สินค้าและคลัง

เปิดได้จาก **ตั้งค่า → ข้อมูลหลัก → สินค้าและคลัง** หรือ **รายการสินค้าและราคา → สินค้าและคลัง**

1. สร้างหน่วย หมวดสินค้า แบรนด์ ประเภท/ชนิดสินค้า และบัญชีอ้างอิงใน Master Data
2. เพิ่มคลังสินค้า แล้วเปิดการควบคุมสต็อกและเลือกคลังเริ่มต้น
3. เพิ่มสินค้า/บริการใน Pop-up เลือกสินค้าในสต็อก ไม่ควบคุมสต็อก หรือบริการ
4. บันทึกยอดยกมาต่อสินค้า/คลัง (และ Serial หากใช้) จากเมนูรับ–จ่าย / โอนสินค้า
5. ตั้งจุดแจ้งเตือนต่อสินค้า/คลัง ดูยอดคงเหลือ Serial Number และประวัติ หรือส่งออก CSV

รายการสินค้าภายในใช้ `crm_price_items` เดียวกับใบเสนอราคา รายละเอียดเพิ่มเติมอยู่ใน `crm_item_details` จึงไม่สร้างทะเบียนราคาซ้ำ และไม่เผยแพร่สินค้าภายในไปยังแค็ตตาล็อกสินค้าสาธารณะ `products` โดยอัตโนมัติ เลือกเชื่อมสินค้าแค็ตตาล็อกเดิมได้สำหรับงานบริการ/สินทรัพย์ ชื่อ ราคา หน่วยและรายละเอียดในเอกสารเก่าเป็น snapshot ไม่เขียนทับย้อนหลัง

VAT เริ่มต้น รอบ Subscription และบัญชีลงรายการเป็นข้อมูลทะเบียนอ้างอิง การคิด VAT ในใบเสนอราคายังตั้งที่ระดับเอกสารตามระบบเดิม ยังไม่มีการลงบัญชีแยกประเภทหรือเรียกเก็บ Subscription อัตโนมัติ

## งานบริการ

สร้างอะไหล่ในเคสและงานซ่อมตามเดิม จากหน้าคลังเลือกจ่ายออก เลือกสินค้า/คลัง และเชื่อมอะไหล่งานบริการ ระบบตรวจรหัสสินค้า/Part Number จำนวน Serial และสินค้าแค็ตตาล็อกที่เชื่อมก่อนตัดสต็อก จากนั้นบันทึกเลขรายการคลังลง `inventory_reference` และชื่อคลังลง `stock_location` ของอะไหล่ อะไหล่หนึ่งรายการจ่ายได้ครั้งเดียว หากลงผิดให้ทำรายการปรับปรุงพร้อมอ้างอิงเลขเดิม ห้ามลบประวัติหรือแก้จำนวนอะไหล่ที่จ่ายแล้ว

## สิทธิ์และความถูกต้อง

ผู้ดูแลระบบที่ยังใช้งานเป็นผู้แก้ทะเบียน คลัง การตั้งค่าและลงรายการสต็อก ผู้มีสิทธิ์ดูใบเสนอราคาหรืองานบริการอ่านข้อมูลคลังตาม RLS ได้ ราคาซื้อยังผ่านสิทธิ์อนุมัติใบเสนอราคาตามเดิม หน้า UI นี้ใช้สิทธิ์ดูรายการราคาในการโหลดข้อมูล

ยอดสต็อกและประวัติไม่เปิดให้ browser เขียนตรง ใช้ RPC ที่ตรวจสิทธิ์และทำงานใน transaction เดียว ล็อกการลงรายการร่วมกับการตั้งค่า ตรวจ request UUID เพื่อไม่ลงซ้ำ และตรวจยอดก่อนโอนหรือจ่าย โหมดไม่อนุญาตติดลบเป็นค่าเริ่มต้น Serial บังคับจำนวนหนึ่งและไม่ติดลบทุกกรณี Unit, stock mode และการติดตาม Serial เปลี่ยนไม่ได้หลังมีประวัติ

ระบบยังไม่ตัดสต็อกอัตโนมัติจากใบเสนอราคาหรือ Sales Order เพราะยังไม่มีขั้นตอนส่งมอบที่ผู้ใช้กำหนด การบันทึกรับ–จ่ายเป็นรายการคลังโดยตรง มีเลขเอกสาร/เหตุผลบังคับและผู้ทำรายการ/เวลาจากเซิร์ฟเวอร์
