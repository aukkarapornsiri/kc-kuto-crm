Marketing email lives under Activities → All emails / My emails / Email templates / Recipient groups. Six starter layouts match the supplied screenshots. Native dialogs trap focus and support Escape. Drafts, templates and audience memberships persist in Supabase with Activities permissions. Group memberships validate linked CRM addresses and exclude blacklisted accounts and inactive contacts. Recipients are frozen and deduplicated when queued; unsubscribed and changed addresses are excluded.

An administrator configures a verified Resend sender, reply-to, postal address and API key through Sender settings. Domain verification does not send email. Keys remain in Vault. Without configuration, saving drafts works and live queueing is blocked. The worker runs every minute, processes five recipients per run, submits one private recipient per request and uses stable idempotency keys. Rate limits retry with delay. An uncertain outcome is recorded for manual review rather than resending automatically. “Accepted by provider” means API acceptance, not confirmed inbox delivery. Cancellation stops pending recipients; an in-flight submission may finish. The unsubscribe endpoint uses an opaque token; GET confirms, POST removes future marketing eligibility. No real marketing messages were sent during implementation tests.

Dashboard → Sales Orders by customer location uses `kc_dw_sales_order_facts.net_amount` for successfully converted SO in THB, excluding VAT, cancelled and voided SO. Opportunities and quotations never substitute for SO. Customer ID joins the CRM billing address; unresolved links/addresses stay in unresolved totals. Product filters sum the selected SO product lines; incomplete product details remain in Unspecified product, never allocated by guesswork. SO counts deduplicate multi-product orders. By Sales, Bangkok SO-date and full-SO value-range filters combine. Other currencies and invalid order/line totals are excluded with visible counts. Total = mapped + unresolved. No street-level position is inferred.

The existing authenticated `kc-dw-sales-sync` feed retains its `sourceBasis: "converted_so"`, integration key and request-id contract. Each row supports `customerId` (exact CRM UUID) or `customerCode` (exact CRM customer code), optional `customerSourceId` for external tracking, and `productLines: [{product, productCode, netAmount}]`. Line values must be nonnegative net amounts after discounts, excluding VAT; their sum cannot exceed the SO net amount. Missing metadata on legacy updates preserves existing links; old source timestamps cannot resurrect cancelled SO. Use explicit `sourceUpdatedAt` for reliable update ordering. Sales identity validation, source-SO uniqueness and audit remain in place. CRM report readers require quotation and customer view permissions; browser writes and gross-profit reads are denied. The feed is empty at implementation time: the page truthfully shows no connected converted SO. No fake SO was persisted and no external producer was changed.
